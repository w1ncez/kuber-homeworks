### Задание 1. Установить кластер k8s с 1 master node

1. Подготовка работы кластера из 5 нод: 1 мастер и 4 рабочие ноды.
2. В качестве CRI — containerd.
3. Запуск etcd производить на мастере.
4. Способ установки выбрать самостоятельно.

-----

Спроектируем будущее развертывание. <br>
5 VM - 1 control plane и 4 workers:
- минимум 2 CPU
- минимум 2 GB RAM (4 для control plane)
- уникальный hostname
- статический IP
- сетевой доступ между всеми VM

К сожалению, на момент выполнения задания в инфраструктуре Yandex Cloud создание новых ВМ было ограничено, пришлось использовать локальный VirtualBox.

Для начала отключим swap, затем установим containerd, kubeadm и kubelet на всех нодах:
<img width="481" height="110" alt="image" src="https://github.com/user-attachments/assets/31eda786-2b19-4a91-9861-55ac86b9f5ad" />

После всех проверок инициируем кластер с master ноды:
```bash
sudo kubeadm init \
  --apiserver-advertise-address=192.168.130.50 \
  --pod-network-cidr=10.244.0.0/16 \
  --cri-socket=unix:///run/containerd/containerd.sock
```
Подключим ноды к кластеру, перед этим получив токен с мастера
```bash
kubeadm token create --print-join-command --ttl=30m

kubeadm join 192.168.130.50:6443 --token <token> \
  --discovery-token-ca-cert-hash sha256:<hash>
```

Установим Calico:
```bash
kubectl create -f https://raw.githubusercontent.com/projectcalico/calico/v3.28.0/manifests/tigera-operator.yaml
```
Подождем 5 минут
```bash
kubectl wait --for=condition=available --timeout=300s deployment/tigera-operator -n tigera-operator
```
Применим манифест с CIDR 10.244.0.0/16
```bash
cat <<EOF | kubectl apply -f -
apiVersion: operator.tigera.io/v1
kind: Installation
metadata:
  name: default
spec:
  calicoNetwork:
    ipPools:
    - blockSize: 26
      cidr: 10.244.0.0/16
      encapsulation: VXLANCrossSubnet
      natOutgoing: Enabled
      nodeSelector: all()
EOF
```
Дождемся, пока все поды поднимутся и проверим статусы далее
```bash
kubectl get pods -n calico-system -w
```
